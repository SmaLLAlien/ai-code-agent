# Слой 5 — изоляция и живое превью

**Результат слоя:** агент каждого проекта работает в отдельном Docker-контейнере без доступа к хосту и
секретам платформы; пользователь видит живое превью проекта рядом с чатом.

**Зачем:** у pi нет песочницы — `bash` выполняется с правами процесса. Без этого слоя платформу нельзя
открывать никому, кроме разработчиков.

**Перед началом:** сверь задачи с текущим кодом и `memorybank.md`; согласуй с DevOps Docker-хост,
сеть и доступ к npm registry.

---

## 5.1 Runner-образ
- `runner/Dockerfile`: `node:24-bookworm-slim`, git; стартер (ref из конфига) с предустановленными
  `node_modules` в слое образа → новый воркспейс стартует без долгого `npm install`.
- `runner/` — отдельный пакет: сервис на Express, куда переезжает код агента из `server/src/agent`,
  транслятор AG-UI и extensions. Общий код — вынести в `packages/`/`shared/` или скопировать (решить,
  записать в memorybank).
- API runner'а — тот же AG-UI endpoint (`POST /run`, `POST /abort`) + `GET /health`.

## 5.2 Оркестрация контейнеров
- `server/src/runners/runner.manager.ts` (через `dockerode` или Docker CLI без shell):
  создать контейнер на чат (volume с воркспейсом), запустить, остановить по простою, удалить при удалении
  чата. Лимиты: CPU, память, pids, таймаут рана.
- Сеть: доступ только к npm registry и активному LLM-провайдеру (или LLM-прокси платформы); к внутренней сети — нет.
- Ключ модели: на первом этапе — env контейнера; целевое решение — LLM-прокси в платформе, чтобы ключ не
  попадал в контейнер (записать решение в memorybank).
- Платформа проксирует `POST /api/chats/:id/run` → runner, стрим проходит без буферизации.

## 5.3 Превью
- В контейнере — `ng serve --host 0.0.0.0 --serve-path /preview/<chatId>/` (base href под подпуть).
- Платформа: `/preview/:id/*` → контейнер:4200 (`http-proxy-middleware`, включая WebSocket для HMR).
- **Фронт:** правая панель с вкладками «Превью» (`<iframe>` + «Обновить» + «Открыть в новой вкладке»).
  Панель статуса: превью запускается / готово / ошибка сборки.
- Альтернатива подпути — wildcard-поддомен `*.preview.<домен>` (одна DNS-запись у DevOps).

## 5.4 Дерево файлов и дифф
- API: `GET /api/chats/:id/files` (дерево без `node_modules`), `GET /api/chats/:id/files/*` (содержимое),
  `GET /api/chats/:id/diff?commit=` (`git show`).
- **Фронт:** вкладки «Файлы» (дерево + просмотр) и «Изменения» (дифф последнего хода по `files_changed`).

---

## Проверка слоя
1. Сборки и тесты зелёные; runner-образ собирается.
2. Безопасность: в чате попросить агента выполнить `cat /etc/passwd` хоста, прочитать файлы платформы,
   обратиться во внутреннюю сеть → недоступно (видно только содержимое контейнера).
3. E2E: изменение через чат → превью в iframe обновляется без ручной перезагрузки.
4. Остановка по простою и повторный запуск контейнера сохраняют воркспейс.
5. Обновить `memorybank.md`.

**Стоп.** Сообщить пользователю, что слой 5 готов к commit + push.
