## 6.1 Скачать zip ✅
- `GET /api/chats/:id/export.zip` (`server/src/workspaces/export.ts`): `git archive --format=zip
  --prefix=<name>/ --add-file=repo.bundle HEAD` — в архив попадают только файлы под git, значит
  `node_modules`, `dist`, `.angular` отсекает `.gitignore` стартера; `repo.bundle` (`git bundle create
  --all`) — полная история (`git clone repo.bundle <dir>`). Перед выгрузкой незакоммиченные изменения
  коммитятся снимком. Без новых зависимостей; требуется git ≥ 2.35 (`--add-file`).
- 409, пока агент работает. Имя: ASCII-slug заголовка или `project-<id>`, `filename*` — исходный заголовок.
- **Фронт:** иконка «Скачать» (Material) в шапке чата; неактивна, пока агент работает.

## 6.2 Публикация по постоянной ссылке
- `POST /api/chats/:id/publish`: в контейнере `ng build --base-href /p/<id>/` → скопировать
  `dist/<name>/browser` в `<dataDir>/published/<id>/` (атомарно: во временную папку + rename).
- Раздача: `/p/:id/*` — `express.static` с теми же cache-заголовками, что для клиента платформы
  (переиспользовать логику `setHeaders` из `server/src/app.ts`, вынести в общую функцию). Работает, даже
  когда контейнер остановлен.
- **Фронт:** кнопка «Опубликовать» → ссылка с «Копировать»; статус сборки публикации в ленте.

## 6.3 Экспорт в GitLab
- Конфиг: `gitlab.url`, `gitlab.groupId`; токен — env `GITLAB_TOKEN` (не в конфиге).
- `POST /api/chats/:id/export/gitlab` `{ name }`: создать проект через GitLab API (`POST /projects`
  с `namespace_id`), `git push` истории воркспейса по https с токеном (через `execFile`, токен не логировать).
- Сохранить URL репозитория в метаданных чата; повторный экспорт — push в тот же проект.
- **Фронт:** «Выгрузить в GitLab» → имя проекта → ссылка на репозиторий.
